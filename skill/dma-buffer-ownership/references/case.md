# 真实案例

本项目持续后台计算，并用三个完整结果槽分别保护正在生成、最近已发布和锁定发送的数据。只有原图、SGM 和小模型结果全部完成、源帧身份一致后，才能发布一组结果。PS_KEY1 锁定最新完整组，发送结束后归还；后台计算不能覆盖发送中的槽。

实际代码位置：firmware/latest_pair.c、board_runtime.c。生命周期检查覆盖生成、发布、锁定、释放及异常流程；真实板端保存的数据包另外验证了同源身份与完整传输。最终使用者确认两张结果成组更新。

该案例说明计算和发送能够使用不同槽并行推进；它保留实际缓存维护、复制和必要排空，不宣称零复制或由槽数直接推出加速倍数。来源为提交材料 evidence/user_acceptance.json、image_provenance.json，以及源码包中的生命周期验证入口。
