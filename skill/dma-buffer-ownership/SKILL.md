# DMA 缓存与有限缓冲归属

## 输入

准备缓冲地址与范围、CPU/PL/网络读写者、缓存属性、状态机、取消和错误路径。先确认哪些设备共用物理端口，哪些只是逻辑独立。

## 执行

1. 对每个缓冲列出生产、就绪、借出、释放条件及源帧身份。只有完整且身份匹配的数据才能发布。
2. 检查 CPU 写后到 PL 或另一核心消费前的发布，以及 DMA 写后 CPU 读取前的失效与屏障。按真实缓存行、地址范围和拥有者判断，不能将所有 clean/invalidate 一律删除。
3. 对发送只读租约、跨核暂存与硬件在途事务分别跟踪。计算结束不等于 DMA 或发送已完成；未排空不能给下一帧复用。
4. 检查取消、超时、断连和重试是否保留旧身份隔离。新状态不能接收上一轮迟到完成。
5. 找等待时先问是否由真实依赖造成。若缓冲被长任务占用，可比较有限暂存、提前启动下一槽和分块消费；同时记录新增 DDR 字节与复制量。
6. 用已有正常、异常、背压与复用检查覆盖改动。选择一组真实输入核对原图和结果身份。无需为了整理文档重跑整套硬件实现。

## 输出

给出简短所有权表、改动前后交接顺序、实际节省的等待、增加的存储/搬运和未验证项。不要用缓存维护地址范围直接宣称 DDR 流量同量减少。

## 已验证案例与失效条件

见 [案例](references/case.md)。本技能针对软件维护缓存与有界 DMA 缓冲；更换为硬件一致性端口、不同 MMU 属性或新的 DMA 时须重新核对。它不能替代传感器同步、硬件 CDC 和时序验证。
