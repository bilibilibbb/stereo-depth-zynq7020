# PYNQ 可复现运行与 Notebook 状态恢复

## 使用场景
用于“Notebook 刚才成功、重跑却失败”、多人交接或演示复现。输入现有 notebook／脚本、Overlay 与 HWH、数据、依赖版本、板卡及镜像信息、恢复方式。先整理当前成果，不自动升级系统镜像或替换运行位流。

## 可重复入口
1. 将硬件配置、输入准备、执行和结果核对拆成有明确输入输出的函数；以参数传递对象，避免依赖未执行单元格留下的变量。保留一个从干净内核按顺序运行的入口。
2. 每次加载 Overlay 后重新获取对应 IP 对象，记录位流和 HWH 身份；不要继续使用上一个 Overlay 的驱动对象。加载与参数初始化分开，不让普通数据处理函数隐式重配置硬件。
3. 每块连续缓冲只有明确的拥有者，区分视图和底层分配。正常结束需等硬件及消费者全部完成后释放；失败时先保持对象、停止新提交、确认硬件静止，再清理。重启 Python 内核本身不是 DMA 排空证明。
4. 使用 `scripts/run_manifest.py` 记录 Python／PYNQ／NumPy 版本以及位流、HWH、输入和契约文件的字节数与 SHA-256；同时保存正确性结果和原始事件表。清单证明身份，不自动证明执行通过。
5. 在适配目标板的干净环境实际重跑入口，比较原始输出。给下一位使用者写最短启动步骤、参数位置和故障恢复路径，而非要求他按研发历史顺序运行所有单元格。

```text
python scripts/run_manifest.py --bit design.bit --hwh design.hwh --input input.bin --contract contract.json
```

脚本只读指定文件并输出 JSON，可重定向保存；流式哈希不整份载入大文件。当前机未安装某包时记录 null，不伪造版本。恢复与验证依据见 [案例](references/case.md)。
