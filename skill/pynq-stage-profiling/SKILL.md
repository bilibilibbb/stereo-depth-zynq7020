# PYNQ 分阶段性能测量

## 测量设计
先确定用户关心的是一次响应、持续完整输出还是算子服务。固定模型、位流、输入、CPU／PL 时钟和并发服务；初始化分配、首次加载、首次编译与预热单独记录，不能任意丢弃慢样本。

用同一 `time.perf_counter_ns` 时钟记录 begin、prepared、submitted、completed、consumed。完成事件必须在 DMA／设备和必要缓存交接结束之后；提交返回不代表硬件完成。自定义任务还需检查结果身份与设备错误。

## 执行与解释
1. 复用相同缓冲，按相同输入交替比较基线与候选，保存每个原始事件和配置。Notebook 绘图、打印、文件保存放在所需指标之外，或作为用户端到端成本明确计入。
2. `scripts/stage_timing.py` 对事件表计算各段样本、中位数和线性插值 P95；只排除显式标记 warmup 的记录。样本少时不把分位数解释为稳定尾延迟。
3. 提交至完成包含排队、访存、DMA、Python 等待与 PL 的共同作用，不能命名为纯 PL 周期。要解释算子内部需另用适用硬件计数或 RTL 证据。
4. 并发任务的各段总和可能重叠，不直接相加推断整机墙钟。连续输出按不同完整结果的完成时刻排序计算，重复身份拒绝计数。
5. 先根据主要耗时选优化：准备占主导看张量整理／复制；传输占主导看粒度与供数；控制占主导看批量提交；只有证据支持时才扩大计算阵列。改动后复用同一事件契约。

## 输出与失效条件
输出同口径前后样本、各段贡献和运行条件。不同设备时钟、缺失完成事件、旧帧重复、输入变化或位流不一致时先修复证据，不制造加速百分比。调用及验证见 [案例](references/case.md)。
