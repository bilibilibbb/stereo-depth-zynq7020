# 通用 PYNQ DMA 缓冲复用与排障

## 输入与适用配置
取得 Overlay 元数据、AXI DMA 的 SG 配置、长度寄存器位宽、MM2S／S2MM 对齐要求、流宽、输入输出形状和 dtype、TLAST 规则及复位方案。下附辅助类限 `C_INCLUDE_SG=0`、双向 AXI simple DMA、独占通道和整块固定输出；不适用于 SG、循环 DMA、VDMA 或可变长压缩输出。

## 开发步骤
1. 用 `pynq.allocate` 分配连续输入与输出，按真实形状和 dtype 算字节，明确字节序及张量布局。NumPy 普通数组的虚拟地址不能当作设备地址。初始化时分配，完成后循环复用，避免逐帧申请与释放连续内存。
2. 从实际 DMA 配置取得最大传输长度和无 DRE 时的地址对齐；不能写死默认 16 KiB。分块须同时调整加速器的块边界、状态延续、TKEEP/TLAST 和输出长度，不只拆 Python 数组。
3. 为输入填充后保持其只读，先准备接收再启动发送／计算，避免输出侧背压。PYNQ simple-DMA 驱动在发送时 flush、接收 wait 完成时 invalidate；自定义 MMIO 主设备需自己保证这些交接。
4. 使用 `scripts/dma_session.py` 将两块缓冲和布局契约固定到一个独占会话。它校验非别名地址、形状、类型、容量与对齐，按接收先行顺序提交，观察 idle/error，在完成后核对实际传输字节。
5. 超时不等于 DMA 已停止。保持会话和缓冲引用，禁止重新提交或释放；先按目标平台复位／排空整个拥有的数据路径并证明静止，再恢复或释放。不能在超时的 finally 中无条件 freebuffer，也不能直接退出仍有 DMA 写入的 Python 进程。
6. 记录分配次数、传输字节和实际完成；初始化、拷贝、Python 显示与硬件服务分别计量。需要流水时增加有上限的槽和明确所有权，不从 Python 线程数推断硬件并行。

## 使用与验证
最小调用骨架见 [用法与真实来源](references/case.md)。辅助类不下载位流、不申请／释放内存、不替用户复位硬件；回调需短时、无阻塞，超时界仅覆盖传输完成等待。

离板行为测试验证接收先行、缓存可见性、两次复用、早 TLAST 短包、错误状态、超时后禁止复用及地址／布局错误。测试替身不能证明真实 DMA、缓存或带宽，目标板用已知输入和对应参考结果补实际验证。
