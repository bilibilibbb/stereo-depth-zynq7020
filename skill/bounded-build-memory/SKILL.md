# 受限内存下的构建与恢复

## 适用任务与输入
用于开发电脑的工具链内存问题。先取得当前工程的进程保护要求、自有进程树身份、物理可用量、提交余量、阶段日志和可复用产物。模型运行时张量压缩属于另一类问题，不能与工具进程驻留混算。

## 方法
1. 同时记录整个任务树的当前私有提交与驻留。退出父进程不代表子进程退出，历史峰值也不代表当前占用。只清理已核实无数据依赖、且目标工程允许清理的占用。
2. 先减少同时存活的数据与工具实例：按模块顺序构建、在阶段间关闭自有工具、流式读取大文件、结果写盘后释放数组。把源码、参数与阶段产物绑定后才恢复，不能复用版本已经变化的中间产物。
3. 对支持的阶段保留断点，失败后选择更小工作集、不同分块或更低并发；不原样重复失败。分块综合仍需同一完整平台的最终资源与时序核对。
4. 使用目标环境的自有任务树硬限制和连续观测。当前项目采用“任务使用量小于实时可用物理内存及提交余量”的策略，预算示例见 `scripts/guard_budget.py`。其他工程按其已确定策略调整，不把该项目偏好推广为唯一标准。
5. 若使用工作集回收，分别记录驻留、私有提交和缺页变化。它可能只是暂时将页移出物理内存；只有减少存活对象、工具实例或工作集需求，才能说明实际需求下降。不要周期性回收所有进程。

## 输出与验证
输出本次峰值来源、实际采用的降低方法、恢复点和下一阶段；保留停止原因与产物身份。运行脚本示例：

```text
python scripts/guard_budget.py --available 2147483648 --commit-headroom 4294967296 --private 536870912 --resident 805306368
```

该脚本只计算字节预算，不监控系统、不结束进程。操作系统限制、采样与保存现场由工程运行器负责；外部程序突发分配不能被周期采样瞬时控制。具体观察和效果见 [案例](references/case.md)。
