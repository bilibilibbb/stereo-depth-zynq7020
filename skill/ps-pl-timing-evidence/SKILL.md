# 双核 PS 与 PL 时间证据核对

## 输入

取得实际源码版本、输入身份、任务依赖、两核分工、共享设备和有限缓冲信息，以及每个时间值的计时起止事件。明确本次用户指标是按键响应、预览接收率还是完整深度输出间隔。

## 执行

1. 建一张简表：任务、执行者、输入何时就绪、完成和释放条件、时间来源。ARM 驱动与缓存时间保留，软件 PL 回放、结果校验等测试工作单列。
2. 确认 PL 周期来自实际 RTL，注明时钟与 DDR 条件。频率尚未物理实现时标为条件频率。
3. 从生产实现还原允许的重叠。两核不得直接按总时间除二；共享 PL、缓存与缓冲冲突必须保留。
4. 用完成事件回答指标。帧间隔取相邻不同完整输出的完成时刻之差；服务时间总和、两帧总周期除二均不能自动替代。
5. 缺少关键量时报告情景和主要敏感项。没有校准依据就不承诺固定百分比误差，也不把情景范围称作严格上下界。
6. 需要性能优化时，以同候选同口径变化排序。计时纠错和删去夹具开销不能计作代码提速；已经改为拍照目标时不额外增加连续深度测量。

## 输出

给出主指标、覆盖条件、分项服务与等待、允许重叠、主要未测项和结论。能用现有证据回答时不新增上板或逐轮综合门槛。

## 已验证案例与失效条件

见 [案例](references/case.md)。本技能已用于区分本项目的三种时间，但不是板端速度预测器。适用源码改变、争用未校准或任务图不完整时，撤回受影响的性能推断，保留仍有效的正确性证据。真实板测、内存和共享硬件保护按所在项目规则执行。
