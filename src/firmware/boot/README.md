# ARM 启动与内存布局

`main.c` 接通 PS_KEY1、PS GEM／lwIP、SD／FatFs、OV5640 配置和双核应用。CPU0 完成一次全局初始化，从 SD 读取配置及标定并更新启动序号，然后初始化相机、计算平台和网络，唤醒 CPU1，进入持续采集、计算和发送的主循环。按键选择最近已完成的同源结果；尚无结果时保留请求，待首份完整结果就绪后发送。

## DDR 布局

计算图使用一套工作区，预览双缓冲及有限结果槽分别管理所有权。工作区按真实 ARM 类型尺寸分配；分配前检查容量、64 字节对齐、整数溢出和地址归属。

| 地址区间（右端不含） | 归属 |
| --- | --- |
| `0x02000000..0x04000000` | 单份代码、只读权重、共享全局对象、BSS、唯一 16 KiB 页表 |
| `0x04000000..0x04800000` | 有界 libc 堆预留；lwIP 自有 2 MiB 堆和包池属于 image 的 BSS，不重复计算 |
| `0x04800000..0x04d00000` | 每核独立 2 MiB 主栈及各异常模式栈，不相互覆盖 |
| `0x07000000..0x07100000` | GEM 描述符非缓存区；实际 RX 64、TX 32 个 8 字节描述符，两环分开起址 |
| `0x10000000..0x18000000` | 计算工作区、输入输出、转换、校正、预览和结果包，启动时一次分配 |
| `0x18000000..0x18400000` | 原采集 RTL 固定四个 DDR 帧区，相机交替使用双缓冲槽 |
| `0x19000000..0x1a000000` | 原 SGM 驱动限定的 DMA 区；顺序放置两份 Census、curve 和 native，未沿用旧 NN/显示别名 |
| `0x1b000000..0x1b200000` | 只读真实校准包，绝不被启动清零或新相机图覆盖 |


表中为互斥地址预留，并非全部实际常驻用量。链接脚本另行校验代码、BSS、堆栈和页表的边界。

## 两核启动与缓存

CPU0 的 SDK 启动执行一次 CRT 初始化。CPU1 从 `ss_cpu1_boot` 进入私有启动段，再调用 `ss_secondary_main`；不重复清零 BSS、初始化计时器或执行 libc 构造。仅 CPU1 启动汇编定义 `USE_AMP=1`，以跳过 SCU／L2 的重复初始化；计算代码和缓存实现使用共享锁维护 L1／L2。相机、模型与网络沿用相同缓存交接和单调时钟。

## SD 文件与构建

`BOOT.BIN` 包含 FSBL、位流和 ARM 应用。`R14CAL.BIN` 保存真实双目标定，`SNAPCFG.BIN` 保存硬件及网络配置，`BOOTSEQ.BIN` 保存带 CRC 的启动序号。固件检查配置、标定及身份的完整性；更新启动镜像时保留板卡已经写回的启动序号。演示包提供配套文件和操作步骤。

恢复工程后，`python run.py firmware` 编译并链接 ARM 应用，完整构建方法见工程根目录的复现说明。地址布局用的 `INERT_layout_probe_NOT_FIRMWARE.elf` 仅为检查夹具，不能下载。
