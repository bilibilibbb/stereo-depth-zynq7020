# Stereo Snapshot Pair / SDP1，版本 1

本协议用于双目拍照系统的实时预览、完整结果传输与接收确认。

系统持续计算，按键选择最新完整结果，使用 format=5；format=3/4 作为兼容格式保留。

板端 TCP 服务：6000 为普通预览，6001 为状态/完整拍照结果。PC 主动连接；两个连接可分别重连。预览保留正在发送的一帧及至多一个最新候选，不能在一帧中途换其内容。结果通道至多一项拍照任务，完整消息可靠接收后一次发布，断开时丢弃残缺消息并保留上次完整结果。

每条消息为 96 字节固定头加 payload；整数头字段使用网络字节序，结果中的 FP32 使用 IEEE754 little endian。payload 使用 CRC32/ISO-HDLC，与 zlib.crc32 一致；头中的 reserved 必须为零。按长度收包，TCP 分片不代表图像边界。错误头、超限长度或 CRC 失败立即断开当前连接，不尝试在坏流中扫描 magic。

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | 4 bytes | ASCII SDP1 |
| 4,5,6 | U8,U8,U16 | version=1，kind，header_bytes=96 |
| 8,12 | U32,U32 | payload_bytes，payload_crc32 |
| 16,24 | U64,U64 | boot_session，shot_id/preview_sequence |
| 32,36 | U32,U32 | epoch，attempt |
| 40,48 | U64,U64 | trigger_us，pair_locked_us |
| 56,64 | U64,U64 | sgm_done_us，model_done_us |
| 72 | U32 | model_id：11459=视差细化网络；0=预览/无模型状态 |
| 76,78 | U16,U16 | width，height |
| 80,82 | U16,U16 | format，flags（bit0=合成测试数据，其余保留） |
| 84,88,92 | U32,U32,U32 | status_code，error_code，reserved=0 |

kind：1=PREVIEW，2=PAIR_RESULT，3=STATUS，4=PAIR_ACK。PREVIEW 的 format=1/RGB888 或 2/YUYV422（BT.601 limited range），最大 640×480；YUYV 宽须为偶数，其他颜色编码应先转换或定义新 format，不能静默套用。预览的 trigger/sgm/model 时间为 0，pair_locked_us 为该预览帧就绪时间。STATUS 的 width/height/format/payload_bytes/CRC 均为 0，错误文字由 PC 按状态码显示，不接受任意 HTML。status_code 为 0=空闲、1=已接受拍摄（旧单拍接口）、2=计算中、3=SGM 就绪、4=回传中、5=忙按被拒绝、6=失败、7=结果尚未就绪且本次请求已结束；error_code 为板端原错误码。

PAIR_ACK 由 PC 在完整校验并保存一组结果后，通过同一结果连接回复。仅 96 字节头，无 payload；boot/shot/epoch/attempt/model_id 原样回显，status_code 存放被确认结果的 payload_crc32；其余长度、CRC、时间、尺寸、format、flags、error 和 reserved 均为 0。确认前断线时，板端保留同一完整结果，从头重传；PC 对完全相同身份和头信息的重复结果再次确认，只发布一次。同身份但 CRC 或元数据不同视为错误。ACK 表示 PC 已完整接收并校验，不表示浏览器已经重绘。

PAIR_RESULT 的 兼容的 format=3 或 4（含校正范围），320×240。payload 按四个连续平面组织：

1. 对应拍照的左目 RGB888，3×W×H 字节。
2. 原始 SGM 整数视差，W×H 字节；有效为 0..63，无效写 255。
3. 有效性标记，W×H 字节。format=3 每值为 0 或 1，表示原始 SGM 有效性；format=4 的 bit0 仍保存原始 SGM 有效性，bit1 表示 SGM 有效且对应左右校正采样均有效，bit2 表示模型视差对应左右校正采样均有效，其余位为 0。bit1 为 1 时 bit0 必须为 1。
4. 模型完整最终视差，4×W×H 字节，FP32 像素单位。

共 691,200 字节载荷、96 字节头。小模型最终输出必须有限且位于其既有 [0,63.99609375] 区间；不得重标定或截断原 FP32。SGM 的 0 是合法视差，不能当无效。format=4 保留原始 SGM 的视差/有效性与全部模型 FP32，仅利用现有两个 ROI 计算显示支持范围，不增加平面、PL 单元或模型计算。右目索引为同行 x-shift；SGM 使用原整数视差，模型沿原显示规则先将 d×256 舍入到最近偶数，再以 (q+128)/256 向下取整得到 shift，越出本行即无效。模型的 bit2 是几何有效性，不能当成独立置信度。

电脑以 bit1 和 bit2 的交集显示两张图，采用相同的无效标记与固定色标，便于对应观察。format=3 未提供校正范围信息，解析时不能将其视为全图几何有效。

format=3/4 的四个板端时间来自同一单调时钟，顺序 trigger≤locked≤sgm_done≤model_done；可报告板端处理时间，但不可直接与 PC 时钟相减得到总延迟。boot_session 每次程序启动必须改变，shot_id 同会话内递增，epoch/attempt 验证重试身份。两张图只有一条完整结果消息，不能独立提交两个不同 shot 的图片。format=5 的请求时间独立，遵循下节规则。

结果源必须先完成 DMA 获取及双核可见性检查。打包读借用期间不释放或复用原始输入、SGM、最终输出；完整打包后才可转移到独立发送缓冲。发送缓冲最后一个 TCP/DMA 消费者结束前不得复用，write/queue 成功不等于电脑已显示。

`sdp_tcp.c` 为 CPU0 的 lwIP raw API 发送器，每次主循环最多复制入队 2,048 字节，不旋等可用窗口。每个连接只保留一条在发消息；结果需 TCP 发送确认和上述 PC 回执都完成，才能结束源缓冲借用。复制入队降低 GEM 对调用者源缓冲的直接依赖，代价为既有 TCP 队列中的一次有界拷贝。预览与结果为两个独立实例；未发送的预览由采集端选择最新完整帧。`board_runtime.c` 以一个待发和一个在发的 96 字节状态头合并最新 STATUS，等待前一条完整消息发送完后再发，不会把状态字节插入结果；STATUS 只需要 TCP 确认，不需要 PAIR_ACK。需要真实板端主循环持续调用 GEM 输入和 TCP 定时服务；模块自身不会初始化 PHY/GEM。

当前小模型适配器中的 sgm_done_us 是首次观察到 SGM 提供者完成（包括原输入发布/解码）的时刻，model_done_us 是首次观察到完整图完成的时刻，存在主循环采样延迟；不是 SGM 硬件最后一拍的精确时刻。所有阶段耗时须按此口径报告。


## 连续计算与按键冻结：format=5

原四个像素平面和 format=4 掩码原样保留，在载荷末尾增加 40 字节元数据，总载荷 691240、总消息 691336 字节。全部载荷（包括元数据）参与原 CRC32。头仍为 96 字节，ACK 机制保持。

头的 boot/shot/epoch/attempt 是**按键请求**身份，trigger_us 是该按键的首次采样时间（经消抖接受后保留），locked/sgm_done/model_done 是选中**源帧**的校正就绪与处理完成时间。按键可以晚于 model_done，也可以早于首个结果，不能要求 trigger≤locked。

| 载荷偏移 | 类型 | 含义 |
|---|---|---|
| 691200 | U64 | 源帧编号，按实际接纳的不同双目输入递增 |
| 691208 / 691212 | U32 / U32 | 源帧 epoch / attempt |
| 691216 | U64 | 相机原始双目 DMA 启动时刻 |
| 691224 | U64 | 完整双目 descriptor 校验及缓存取得时刻 |
| 691232 | U64 | 按键请求选定此完整结果的时刻 |

元数据均为网络字节序。必须有非零源帧、epoch、attempt，采集启动≤取得完整双目≤校正就绪≤SGM完成≤模型完成≤选中，同时按键时间≤选中。不将 DMA 启动/取得冒称曝光时刻。源帧与按键共享 boot_session；多个递增请求可选中同一源帧，各次请求分别确认，断线重传仍使用原请求、原选中时刻和原 CRC。

有完整结果时，接受按键后直接保留该缓冲并优先开始 TCP 发送，不复制整张图；尚无结果时发送 STATUS 2 并保留唯一请求及原始按键时间，在第一份完整结果发布时自动锁定发送，无需再次按键。按处理完成顺序选择，可接用按键前已经启动的计算，不重新采集或重启推理。等待和发送期间的再次按键报告忙，不替换请求也不积压；长按只接受一次。后台计算出错会结束等待并报告失败，不发布半成品。STATUS 7 的旧“不等待”含义保留兼容，当前正常按键路径不再发送它。模型每个接纳源帧只算一次，按键不启动推理。后台始终通过三个有限结果缓冲轮换：一个可被发送保留，另外两个承接最新结果与下一次写入；只有完整打包、CRC 和真实源读借用释放后才发布新结果。发送借用直到 TCP 和 PC 完整校验回执均结束才释放。

协议记录请求编号与源帧编号；源帧年龄为“选中−取得完整双目”，按键等待为“选中−按键采样”，SGM/模型处理时间从源帧相机启动算起。这些值不包括完整网络传输或浏览器绘制；PC 收齐 ACK 仍不是实际显示确认。预览和结果的更新频率分别报告。
